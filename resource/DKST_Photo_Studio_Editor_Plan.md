# DKST Photo Studio 편집창 전환 계획

작성일: 2026-10-11. 상태: 1차 구현 및 로컬 검증 완료. 원격 ComfyUI 배포·실사용 검증 전.

## 구현 결과 (2026-10-11)

큰 DOM 편집창, 32개 보정값, 임시 설정/적용/취소, Undo/Redo, 프리셋, Auto,
원본 비교/히스토그램, 이미지·깊이맵 선택/파일 업로드, 초점 찍기와 마커를 구현했다.
기존 설정 복원과 엔진은 유지한다. Python 미리보기 API는 전체 그래프를 실행하지 않는다.

파일·배치 스냅샷은 정밀도와 알파를 맞추기 위해 일반 Load Image 대신 새
`DKST Color (Photo Studio Source)`로 연결한다. 기존 Load Image 연결을 미리볼 때는
설치된 코어 로더를 호출하여 실제 워크플로의 이미지 해석을 따른다.

빠른 모드는 1024px 프록시이며 픽셀 효과의 차이를 표시한다. 1차 구현에서는 커널의
배율 보정 대신 원본 해상도 처리 옵션으로 정확한 엔진 결과를 확인한다. 표시 PNG는
최대 1400px이므로 확대 기능은 원본 1:1 픽셀 표시를 뜻하지 않는다. 이동은 스크롤로 제공한다.
이미지 선택은 Undo/Redo 이력에 포함하지 않는다. 새 실행 입력은 Refresh Input으로 반영한다.

CPU 텐서 캐시는 30분, 16개, 512MiB로 제한한다. 캡처가 사라지면 Photo Studio의
IS_CHANGED 값이 바뀌어 다음 정상 실행에서 입력을 다시 캡처한다. 상위 노드의 정상
실행 캐시는 유지된다. 보정 입력 링크가 연결된 항목은 편집을 잠그며, 미리보기의
외부 연결값은 현재 저장된 위젯값을 사용한다는 안내를 표시한다.

Python 엔진/API 테스트와 JavaScript 회귀 테스트, 실제 엔진을 연결한 격리 브라우저
하네스로 검증했다. 브라우저에서 40% 그래프 줌과 760×600 / 430×800 창을 확인했다.
원격 서버의 실제 일반 노드/Nodes 2.0 및 서브그래프 승격 입력 조합은 배포 후 검증할 항목이다.
아래 내용은 원래 설계와 검증 기준으로 보관한다.

## 1. 목표와 결정

사용자가 선택한 형태는 **같은 ComfyUI 브라우저에서 화면 대부분을 덮는 편집창**이다.
Photo Studio의 `Open Photo Studio` 버튼과 이미지 노드의 우클릭 메뉴로 열고,
이미지와 조절 패널을 함께 보면서 편집한다. 이미 로드된 이미지 파일이나 기존 출력
이미지가 있으면 워크플로 실행 없이 편집 입력을 확보한다. `적용`은 보정값을 노드에
저장하며, 다음 워크플로 실행에서 원본 입력에 그 값을 적용한다.

편집창은 그래프의 CSS 변환 영역 밖에 배치한다. 브라우저 화면 크기로 레이아웃을
계산하고, 그래프 확대·축소와 이미지 확대·축소를 독립적으로 관리한다.
기존 섹션 제목의 커스텀 캔버스 렌더링을 편집창으로 가져오지 않는다.

Camera Raw는 화면 구성과 편집 동작의 참고다. 현재 Photo Studio의 IMAGE 보정 엔진,
파라미터 의미와 범위를 유지하며 RAW 현상이나 Adobe와 동일한 결과를 목표로 삼지 않는다.

## 2. 확인한 구현 사례

| 사례 | 확인한 방식 | DKST에 참고할 부분 |

| [Comfy Canvas](https://github.com/Zlata-Salyukova/Comfy-Canvas) | 노드 버튼과 메뉴로 모달 iframe 실행, 노드별 세션 저장 | 노드는 작게 유지하고 편집 작업을 별도 화면으로 이동 |
| [ComfyUI 기본 Mask Editor](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/composables/maskeditor/useMaskEditor.ts) | 화면 약 90%를 사용하는 모달 편집창 | 큰 이미지 영역, 스크롤 패널, 입력 포커스와 적용/취소 |

TrixLoader의 `web/js/trix_camera_raw.js`와 Comfy Canvas의
`web/js/comfyCanvasOverlay.js`를 읽어 실제 오버레이 생성 방식도 확인했다.
구조를 참고하고 DKST용 편집창을 독립적으로 구현한다.

## 3. 현재 DKST 구조와 추가할 부분

- `dinki_photo_studio.py`의 `CONTROLS`에 32개 보정 항목과 기본값·범위·간격이 정의되어 있다.
- `apply()` / `_process()`가 실제 보정 엔진이다. 최종 IMAGE 출력은 이 엔진을 계속 사용한다.
- `execute()`의 UI 데이터는 현재 깊이맵 미리보기와 Auto 제안이다. 보정 전 이미지와
  편집 세션을 제공하는 경로는 없다.
- 기존 `/dinki/photo-studio/presets` API와 사용자별 프리셋 저장을 재사용한다.
- `dinki_photo_studio.js`에는 이름 기반 설정 저장과 과거 위치 기반 값 복원 코드가 있다.
  새 편집창에서도 이 호환성을 유지해야 한다.

**핵심 추가 작업은 원본 입력 확보와 빠른 미리보기다.** 출력 이미지에 보정을 다시
누적하지 않고, 같은 보정 전 입력에 매번 현재 임시 설정을 적용해야 한다.

## 4. 화면과 사용자 동작

### 작은 노드

노드에는 `image` / `depth_image` 입력, `image` 출력, `Active`, `Preset`,
`Open Photo Studio`, 작은 결과 썸네일과 입력 준비 상태를 둔다.
Save / Save As / Auto / Reset 및 전체 보정 슬라이더는 편집창으로 옮긴다.

Python 입력 정의와 원래 위젯값은 실행 및 기존 워크플로 호환용으로 유지한다.
기본 화면에서는 보정 위젯을 숨기고, 입력으로 변환되거나 연결된 보정 항목은
연결과 소켓을 유지한다. 연결된 값은 외부 입력으로 표시하고 직접 편집할 수 없게 한다.
서브그래프에 승격된 항목도 같은 원칙을 적용한다.

### 이미지 노드의 우클릭 진입

Load Image 및 실제 이미지 미리보기를 제공하는 노드에 `Open in Photo Studio`를
추가한다. 이미지가 여러 장이면 현재 선택된 이미지로 연다. 이미지가 없거나 정확한
파일 참조를 얻을 수 없는 노드는 가능한 입력 확보 방법을 안내한다.

Photo Studio 자체에서 열면 그 노드의 설정을 편집한다. 다른 이미지 노드에서 열면
해당 이미지를 기준으로 새 편집 세션을 만들고, `보정 노드로 적용`을 제공한다.
이미지를 출력하는 노드에서는 선택한 IMAGE 출력에 새 Photo Studio를 연결한다.
Preview Image / Save Image처럼 IMAGE 출력이 없는 노드는 실제 IMAGE 입력 링크의
출발점을 대상으로 삼는다. 기존 분기는 자동으로 모두 바꾸지 않고, 첫 버전은
새 Photo Studio 분기를 추가하여 사용자가 후속 연결을 선택하게 한다.

사용자가 파일을 직접 불러오는 경우에는 입력 파일과 보정값을 함께 재현할 수 있도록
Load Image → Photo Studio 연결을 만든다. 원본 파일을 덮어쓰거나 보정 이미지를
원본으로 교체하는 동작은 기본 적용에서 수행하지 않는다.

### 큰 편집창

| 영역 | 구성 |
| --- | --- |
| 상단 | Photo Studio 제목, 프리셋, Auto, Reset, Undo / Redo |
| 중앙 | 큰 보정 이미지, 원본 보기, 좌우 비교, Fit / 확대·축소 / 이동 |
| 오른쪽 | 히스토그램, Light / Color / Effects / Detail / Optics / Lens Blur 접이식 패널 |
| 하단 | 입력 갱신 상태, 미리보기 상태, 취소, 적용 |

넓은 화면은 이미지와 약 320px 조절 패널을 나란히 배치한다. 작은 화면에서는
조절 패널을 전환할 수 있게 하고, 낮은 창에서는 패널 내부만 스크롤한다.
상단과 하단의 필수 동작은 항상 보인다. 편집창 밖 클릭으로 닫히지 않는다.

Lens Blur에는 깊이맵 보기와 클릭으로 초점 선택을 제공한다. 클릭 위치는 이미지의
정규화 좌표로 저장하고, 줌·팬을 역변환하여 샘플링한다. 왜곡 보정을 켠 경우에는
표시 이미지와 깊이맵의 좌표 변환을 일치시킨다.

### 깊이맵 선택

사용자가 제안한 방식에 따라 깊이맵도 워크플로에 이미 존재하는 이미지에서 선택한다.
Lens Blur 패널에 `깊이맵 선택`을 두고 다음 경로를 제공한다.

1. 현재 Photo Studio의 `depth_image`에 연결된 이미지가 확보되어 있으면 우선 사용한다.
2. 현재 워크플로의 로드된 이미지와 기존 출력 이미지를 썸네일 목록으로 보여준다.
   노드 이름, 선택 이미지, 해상도를 함께 표시하고 사용자가 깊이맵을 지정한다.
3. `파일 불러오기`로 별도의 깊이맵을 선택할 수 있다.

첫 버전의 목록은 파일 또는 기존 미리보기 참조를 확보할 수 있는 이미지만 포함한다.
아직 실행되지 않은 깊이 추정 노드의 결과는 실행이 필요하다고 표시한다.
일반 이미지가 회색이라는 이유만으로 깊이맵에 자동 지정하지 않는다.

원본과 깊이맵은 같은 장면과 구도를 가져야 한다. 해상도는 달라도 되지만 종횡비는
기존 `_prepare_depth()`의 검증 기준에 맞아야 한다. 종횡비가 맞더라도 Crop / 회전 /
뒤집기 이력이 다르면 좌표가 어긋날 수 있으므로 원본과 깊이맵을 나란히 확인할 수
있게 한다. 구도가 다른 깊이맵을 임의로 잘라 맞추지 않는다.

깊이 데이터는 파일이나 캐시의 원래 정밀도로 읽고, 썸네일은 표시용으로 사용한다.
`흰색이 가까움` 옵션과 깊이맵 미리보기, 클릭 초점 선택을 제공한다.
깊이맵 없이 Light / Color / Effects / Detail / Optics 편집은 가능하며,
Lens Blur 활성화에는 유효한 깊이맵이 필요하다.

편집 중 선택은 임시 상태로 관리한다. `적용` 때 선택한 노드의 IMAGE 출처를
Photo Studio의 `depth_image`에 연결한다. 출력이 없는 미리보기 노드는 그 IMAGE
입력 링크의 출발점을 사용한다. 파일을 직접 가져왔다면 깊이맵용 Load Image를
추가하여 연결한다. `취소`는 기존 연결을 바꾸지 않는다.
프리셋에는 이미지·깊이맵 참조를 넣지 않고, 워크플로의 링크/파일 참조로 복원한다.
정확한 출력 또는 배치 항목을 링크로 재현할 수 없는 이미지 스냅샷은 별도 입력 파일로
확보하는 방식을 사용하고, 원래 출력 전체에 연결한 것처럼 처리하지 않는다.

### 편집 상태

1. 열 때 노드의 현재 설정을 복사하여 임시 편집 상태를 만든다.
2. 슬라이더·Auto·프리셋 선택은 임시 상태와 미리보기를 변경한다.
3. Undo / Redo는 임시 설정의 변경 단위로 기록한다. 슬라이더 드래그 하나를
   하나의 이력으로 묶는다.
4. `적용`은 편집 가능한 값을 노드에 한 번에 반영하고 그래프 변경을 알린다.
   기본 동작은 설정 저장과 창 닫기다. 최종 IMAGE 출력은 다음 정상 실행에서 갱신된다.
5. `취소`와 Escape는 임시 변경을 버리고 닫는다. 닫은 후 포커스를 원래 버튼으로 돌린다.
6. 프리셋 저장은 별도의 영구 동작이다. `취소`가 이미 저장한 프리셋까지 지우지는 않는다.

편집 중 노드가 삭제되거나 워크플로가 전환되면 세션을 정리한다. 다른 노드의 값으로
자동 전환하지 않는다. 새 실행으로 입력이 바뀌면 임시 설정을 유지하며 새 입력 사용
여부를 명확하게 표시한다.

## 5. 입력 확보와 미리보기 설계

### 보정 전 입력

입력 확보는 다음 우선순위와 정확성 기준으로 처리한다.

| 경로 | 첫 워크플로 실행 필요 여부 | 판단 기준 |
| --- | --- | --- |
| 직접 연결된 Load Image의 선택 파일 | 필요 없음 | 파일 참조로 원본을 서버에서 읽음. 로더의 EXIF 방향·알파 등 해석과 일치시킴 |
| 우클릭한 노드의 기존 출력 이미지 | 다시 실행할 필요 없음 | 선택된 파일 descriptor로 읽음. 최신 텐서가 아닌 저장된 출력 이미지 스냅샷임을 표시 |
| Photo Studio의 이전 실행 입력 캐시 | 필요 없음 | 같은 입력 버전과 유효한 세션을 확인 |
| 편집창에서 파일 불러오기 | 필요 없음 | ComfyUI 입력 이미지로 등록하고 재현 가능한 파일 참조를 유지 |
| 파일/미리보기/입력 캐시가 없는 IMAGE 경로 | 필요 | 상위 연산을 실제 실행해야 입력을 얻을 수 있음 |

실행 없이 확보한 파일은 별도 세션 API를 통해 Python 보정 엔진에 전달한다.
서버에서는 ComfyUI의 파일 descriptor를 해석하고 이미지 데이터를 읽는다.
화면에 표시된 축소 캔버스를 캡처하는 대신 원래 파일을 읽는 것을 우선한다.
로드·미리보기 노드와 Photo Studio에서 각각 어떻게 원본을 찾는지 분리하여 구현한다.

임의의 상위 노드를 재귀 탐색하여 처음 발견한 이미지를 실제 입력으로 간주하지 않는다.
중간의 Crop / Resize / 합성 / 색 보정 등이 아직 실행되지 않았다면 발견한 원본은
현재 연결 입력과 다르다. 정확한 파일 경로를 확인할 수 없는 경우에는 참고 이미지임을
표시하거나 실행을 요구한다. 입력 버전이 바뀐 뒤의 오래된 출력도 최신 입력처럼 표시하지 않는다.

Photo Studio가 정상 실행될 때에는 보정 전 IMAGE와 깊이맵을 편집용 캐시에 확보한다.
기본 미리보기는 첫 번째 배치 항목이며, 우클릭 진입에서는 선택된 이미지를 사용한다.
현재 노드의 최종 실행은 기존처럼 전체 배치에 같은 설정을 적용한다. 편집한 한 장과
전체 배치 적용 범위를 화면에서 구분하고, 배치별 개별 설정은 후속 확장으로 둔다.

캐시의 원본은 detached CPU 데이터로 관리한다. 원본 GPU 텐서 참조를 장기간
보관하지 않는다. 브라우저에는 입력 버전, 세션 토큰, 해상도와 이미지 URL을 보낸다.
워크플로 JSON에는 이미지나 임시 캐시 토큰을 넣지 않는다.

캐시는 사용자와 실행 세션별로 분리하고 노드 ID만으로 조회하지 않는다.
메모리 총량·세션 수·유효 시간을 제한한다. 구현 시 초기 상한 후보는
256MiB / 4세션 / 마지막 사용 후 10분이며 실제 입력 크기로 조정한다.
캐시가 만료되면 명시적으로 입력 갱신을 요구한다.

파일과 기존 이미지 참조를 얻을 수 있으면 첫 실행 전에도 이미지 편집을 제공한다.
어떤 경로로도 입력을 확보하지 못했을 때에는 설정창만 열고 입력이 필요하다고 표시한다.
연결된 임의 노드의 IMAGE 텐서를 브라우저에서 직접 읽을 수 있다고 가정하지 않는다.
편집 중 슬라이더 변경은 워크플로 실행을 발생시키지 않는다.

ComfyUI 실행 캐시로 Photo Studio의 `execute()`가 생략될 수 있으므로,
입력 갱신용 nonce로 해당 노드의 재실행을 유도할 수 있는지 첫 단계에서 검증한다.
필요하면 기본값을 가진 선택 입력을 추가하고 기존 보정값 복원과 분리한다.
노드를 출력으로 사용하지 않은 그래프에서도 입력 확보 동작을 명확히 해야 한다.

### 미리보기 엔진

**첫 버전은 서버의 기존 Python 보정 엔진을 재사용한다.** 브라우저에 32개 보정
연산을 새로 구현하면 같은 값의 미리보기와 최종 출력이 달라질 위험이 커진다.

- 설정 스키마 API: `CONTROLS`로부터 이름·종류·범위·기본값·툴팁을 제공한다.
  프런트엔드의 범위를 중복 정의하지 않는다.
- 세션 이미지 API: 해당 세션의 보정 전 이미지와 깊이맵 표시 데이터를 제공한다.
- 미리보기 API: 세션 토큰, 입력 버전, 임시 설정, 품질, 요청 순번을 받아 이미지를 돌려준다.
  UI 미리보기 실행은 노드 설정과 최종 출력 캐시를 변경하지 않는다.
- 계산은 aiohttp 이벤트 루프 밖의 제한된 작업자에서 처리한다. 첫 구현은 CPU 작업자를
  기준으로 측정하며 GPU 실행과의 경쟁을 피한다.

슬라이더 입력은 약 150~250ms 간격으로 묶고, 실행 중인 작업 뒤에는 최신 요청만 남긴다.
이전 HTTP 요청을 중단하는 것과 서버 계산을 중단하는 것은 다르므로 서버도 세션별
중복 계산을 제한한다. 늦게 도착한 응답은 입력 버전·요청 순번을 비교하여 버린다.

조작 중 미리보기는 긴 변 768~1024px부터 측정한다. 정확한 크기와 지연은 원격 서버에서
색 보정과 Lens Blur를 따로 측정하여 결정한다. 실시간 60fps를 약속하지 않는다.
필요하면 사용자가 정밀 미리보기를 요청할 수 있게 한다.

**축소 미리보기와 원본 품질은 구분해야 한다.** 현재 엔진의 Texture / Clarity /
Sharpening / Glow 등은 픽셀 단위 커널이고, Grain과 Lens Blur도 해상도 영향을 받는다.
축소본에 같은 수치를 적용하는 것만으로 최종 출력과 일치하지 않는다.
축소 미리보기의 커널 크기는 원본 대비 배율을 고려하고, 기본 최종 처리 경로는 유지한다.
정밀 모드에서는 선택한 원본 항목 전체를 처리한 뒤 화면에 표시한다.
`100%` 표시는 원본 픽셀 미리보기를 확보했을 때 사용하고 프록시 확대와 구분한다.

노드 실행에서 얻은 텐서 경로는 이미지 인코딩을 표시용으로만 사용하고 최종 IMAGE
텐서를 PNG/JPEG로 왕복시키지 않는다. 기존 출력 파일에서 연 편집 세션은 그 파일의
정밀도를 사용하므로 텐서 캐시 경로와 구분한다.
RGB/RGBA, 투명 배경, 표시 색공간을 일관되게 처리한다. 깊이값 샘플링은 표시용
8bit 이미지와 계산용 데이터의 차이를 고려한다.

Auto와 White Balance Auto의 통계도 같은 입력 버전에 연결한다. 임시 설정 적용으로
원본 통계가 누적 변경되지 않게 한다.

## 6. 구현 순서

1. **입력과 호환성 검증**
   - Load Image 파일, 기존 출력 이미지, 직접 파일 불러오기, 원본 캐시의 순서로
     입력을 확보하고 첫 실행 없이 미리보기가 가능한지 검증한다.
   - UI 토큰 전달, 캐시 만료 후 갱신, 중간 연산이 있는 입력의 정확성을 검증한다.
   - 일반 노드와 Nodes 2.0에서 위젯을 숨겨도 API 프롬프트와 연결된 소켓이 유지되는지 확인한다.
   - 이전 저장 포맷, 신규 선택 입력, 서브그래프 인스턴스의 구분을 검증한다.

2. **편집창과 설정 연결**
   - 새 편집창 모듈과 범위를 제한한 CSS를 추가한다.
   - 그래프 변환 영역 밖의 모달 DOM으로 연다. 가능하면 native dialog를 사용하여
     포커스와 배경 입력 차단을 관리하고 설치된 프런트엔드와의 충돌을 검증한다.
   - 작은 노드, 이미지 노드 우클릭 메뉴, 6개 패널, 임시 상태, 적용/취소, 프리셋,
     Undo / Redo를 연결한다. 새 보정 노드로 적용할 때 IMAGE 출력과 입력 링크를 확인한다.

3. **미리보기 API와 표시**
   - 기존 엔진을 호출하는 제한된 작업자, 요청 병합, 오래된 응답 무시를 구현한다.
   - 원본/보정 비교, 히스토그램, 줌·팬, 입력 없음/만료/실패 상태를 연결한다.
   - Proxy와 정밀 모드의 품질 및 실제 지연을 측정한다.

4. **Lens Blur와 상태 복원**
   - 워크플로 이미지 선택 목록, 깊이맵 파일 불러오기, 적용 시 depth_image 연결을 구현한다.
   - 깊이맵, 초점 클릭, 깊이 방향, 왜곡 시 좌표 정합을 연결한다.
   - 워크플로 저장/복구, 복제, 노드 삭제, 실행 중 새 입력, 창 재개방을 처리한다.

5. **실제 ComfyUI에서 완료 검증**
   - 좁은/낮은 창과 초기 줌 25/50/80/100/200%에서 생성하고 창 크기와 줌을 변경한다.
   - 일반 노드와 Nodes 2.0, 원격 브라우저, 두 워크플로의 같은 노드 ID를 확인한다.
   - 프리셋, Auto, Apply/Cancel, Undo/Redo, 느린 네트워크, 응답 순서 역전과 캐시 만료를 검증한다.
   - RGB/RGBA, 배치, 깊이맵 없음/낮은 해상도, 연결된 보정 입력과 서브그래프를 검증한다.
   - 실행 전 Load Image, 생성 후 선택된 미리보기, 여러 출력/배치, 오래된 출력,
     Crop 등 미실행 중간 연산, 노드 분기 추가와 파일 기반 워크플로 복원을 검증한다.
   - 깊이맵 선택·취소·재연결, 다른 해상도/종횡비, 깊이 방향, 파일 정밀도,
     선택한 배치 항목의 재현과 원본/깊이맵 입력 버전을 검증한다.
   - 중립/Inactive의 기존 정확한 bypass와 전체 보정 엔진 테스트가 통과해야 한다.
   - 정밀 미리보기의 인코딩 전 텐서는 같은 입력·설정의 최종 처리와 비교한다.
     축소 미리보기는 별도 허용 오차로 평가하고 픽셀 완전 일치를 주장하지 않는다.

첫 버전에는 현재 32개 보정값과 편집에 필요한 표시 기능을 담는다.

브라우저 GPU 미리보기는 실제 서버 지연 측정 후 필요할 때 별도로 검토한다.

## 완료 조건

작은 Photo Studio 노드에서 편집창을 열어 원본과 보정 결과를 비교하고,
모든 기존 보정 항목을 조절한 뒤 적용·저장·재개방할 수 있어야 한다.
Load Image의 파일과 이미 생성된 출력은 전체 워크플로 재실행 없이 편집할 수 있어야 한다.
취소는 노드 설정을 바꾸지 않아야 하며, 창 크기와 그래프 초기 줌을 바꿔도
제목/조절 항목이 겹치지 않아야 한다. 슬라이더 조작으로 전체 워크플로가 실행되지
않아야 하고, 기존 워크플로와 최종 IMAGE 결과가 호환되어야 한다.
