# DKST Util (Node Change) 3·4그룹 확장 계획

작성일: 2026-10-14. 아래 계획에 따라 3·4그룹 노드를 구현했다.
사용 방법은 [Node Utils](DINKI_Node_Utils.md)의 3·4그룹 설명을 참고한다.

## 현재 구조와 결론

`dinki_switch.py`의 `DINKI_Node_Change`는 `active: BOOLEAN`을 사용한다.
true는 그룹 1, false는 그룹 2이며, `switch: BOOLEAN` 출력도 같은 값을 반환한다.
실제 대상 노드의 실행 모드는 `js/dinki_nodes.js`의 `applyNodeChange()`가 변경한다.

3·4그룹 대응은 가능하다. 새 노드에서는 `active`를 **1부터 그룹 수까지의
정수 선택값**으로 정의하는 방식을 권장한다. Boolean 하나로는 세 가지 이상의
상태를 표현할 수 없으므로 새 노드의 입력과 출력 계약을 별도로 만든다.

## 추가할 노드

| 표시 이름 | 클래스 ID 제안 | 그룹 수 | active |
| --- | --- | --- | --- |
| DKST Util (Node Change) | DINKI_Node_Change, 기존 유지 | 2 | BOOLEAN |
| DKST Util (Node Change 3 Groups) | DINKI_Node_Change_3 | 3 | INT, 1~3 |
| DKST Util (Node Change 4 Groups) | DINKI_Node_Change_4 | 4 | INT, 1~4 |

새 버전은 그룹 하나만 선택하는 방식이다. 여러 그룹을 동시에 켜는 기능은
별도의 동작이므로 이번 범위에 포함하지 않는다. Auto Node Change 확장도
이번 범위에 포함하지 않는다.

## active 선택 방식

| 방식 | 장점 | 검토 결과 |
| --- | --- | --- |
| INT 선택값 1~N | 그룹 번호와 값이 일치하고, 입력·출력의 의미가 명확함 | 기본 구현으로 권장 |
| 고정 항목 드롭다운 | 여러 그룹 중 하나를 고르기 편함 | 대안. 문자열 항목을 사용하면 서버에서 번호로 변환 필요 |
| 그룹별 Boolean 토글 | 기존 토글과 비슷함 | 복수 선택·전체 해제 상태의 우선순위 규칙이 필요해 제외 |
| 그룹 이름 버튼 3·4개 | 이름을 보고 바로 선택 가능 | 추가 UI 후보. classic·Nodes 2.0·서브그래프 승격 호환 검증 필요 |

기본 구현은 `active: INT`에 `default=1`, `min=1`, `max=N`, `step=1`을 둔다.
JavaScript와 Python은 같은 유효 범위 규칙을 사용한다. 잘못된 값은 그룹 1로
임의 전환하지 않고 유효성 오류로 처리한다. 프런트엔드에서는 그 값으로
대상 모드를 변경하지 않는다.

기존처럼 기본 화면에는 `active`만 표시하고, `node_ids_1~N`,
`disable_mode`, `group_1_label~N`은 advanced 입력으로 둔다.
그룹 이름은 빈 값에 `Group N`을 적용한다. 숫자 선택 UI에서 사용자 지정 이름이
잘 보이도록 현재 선택 이름 표시를 검토하되, 이름 변경으로 저장된 선택 번호가
바뀌지는 않게 한다. 버튼이나 드롭다운 표시를 추가할 경우에도 저장 기준은
그룹 번호로 유지한다.

## 대상 노드 활성화 규칙

1. 각 `node_ids_N`을 ID 집합으로 읽는다.
2. 선택한 그룹에 속한 ID는 normal 모드 0으로 설정한다.
3. 나머지 그룹에만 속한 ID는 Bypass 4 또는 Mute 2로 설정한다.
4. 어느 그룹에도 없는 대상은 현재 모드를 유지한다.
5. 자기 자신, 존재하지 않는 ID, 빈 항목은 무시한다.

겹치는 ID는 선택한 그룹에 포함되어 있으면 활성화하는 규칙을 우선한다.
예를 들어 그룹 1·2에만 공통으로 있는 ID는 그룹 1 또는 2 선택 시 활성화되고,
그룹 3 선택 시 비활성화된다. 항상 실행할 공통 노드는 모든 그룹에 등록하거나
제어 대상에서 제외한다. 제어 범위는 해당 노드가 속한 graph/subgraph다.

## 인덱스 출력과 다중 분기 연결

새 노드는 `index: INT` 출력 하나를 제공한다. 출력값은 `active`와 같은
1부터 시작하는 그룹 인덱스이며, 그룹별 Boolean 출력은 추가하지 않는다.

| 선택 그룹 | active | index 출력 |
| --- | --- | --- |
| Group 1 | 1 | 1 |
| Group 2 | 2 | 2 |
| Group 3 | 3 | 3 |
| Group 4, 4그룹 버전 | 4 | 4 |

예를 들어 4그룹에서 `active=3`이면 그룹 3이 활성화되고 `index=3`이 출력된다.
이 인덱스는 같은 번호 체계를 사용하는 다중 입력 선택 노드에 연결한다.
연결할 노드가 0부터 시작하는 인덱스를 요구하면 별도 변환으로 `index - 1`을
사용한다. 기존 Boolean If/Else Switch 또는 Branch와는 직접 연결하지 않는다.
전용 다중 분기 lazy 라우터는 후속 확장 후보로 두며, 추가할 경우 `index: INT`를
입력받아 선택한 그룹의 입력만 평가하도록 설계한다.

대상 노드 Mute/Bypass는 큐 제출 전에 프런트엔드에서 적용해야 한다.
이번 구현의 `active`는 수동 위젯 또는 서브그래프 승격 위젯으로 사용한다.
백엔드 실행 중 계산된 INT 입력으로 같은 실행의 노드 모드를 바꾸는 기능은
지원하지 않는다. 이미 제출한 실행도 선택 변경으로 갱신되지 않는다.

## 구현 순서

1. `dinki_switch.py`: 새 다중 그룹 베이스와 3·4그룹 클래스를 추가하고,
   그룹 수에 따라 입력 정의를 생성한다. 두 새 클래스 모두 `index: INT` 출력
   하나를 제공한다. 기존 2그룹 클래스 계약은 유지한다.
2. `js/dinki_nodes.js`: 다중 그룹 적용 함수를 만들고, 공통 lifecycle 등록 함수가
   그룹 수와 출력 정의, 선택 UI 동기화 함수를 받도록 확장한다.
   현재 Boolean 전용 `on/off` 라벨 동기화와 `switch` 출력 복원 코드를 분리한다.
3. 서브그래프 승격과 중첩 승격에서 숫자 선택값을 전달하고, workflow 로드 및
   탭 전환 후 선택을 재적용한다. 기존 compact 크기 보존 기능도 재사용한다.
4. `__init__.py`에 클래스와 표시 이름을 등록하고, Node Catalog 및 Node Utils
   문서에 선택값·중복 ID·출력 연결 예제를 추가한다.
5. 새 Python/JavaScript 검증을 추가하고 기존 Node Change, Auto Node Change,
   Node Switch의 관련 테스트를 실행한다.

## 검증 기준

- 3그룹과 4그룹의 모든 선택값에서 선택 그룹만 활성화되는지 확인한다.
- Bypass/Mute, 중복 ID, 부분 공유 ID, 빈 그룹, 자기 ID, 잘못된 값 처리를 확인한다.
- 새 노드는 INT 출력 하나만 제공하고, index가 프런트엔드의 active 및 선택 그룹 번호와 일치해야 한다.
- classic 및 Nodes 2.0, 저장·재로드, advanced 펼침·접힘, 서브그래프와 중첩 승격을 확인한다.
- 라벨 수정으로 선택값이나 대상 모드가 바뀌지 않아야 한다.
- 상태 변화가 없으면 불필요한 redraw를 만들지 않아야 한다.
- 기존 2그룹과 Auto Node Change의 Boolean 출력·저장 워크플로 동작을 보존해야 한다.

## 후속 확장 후보

Auto 버전을 추가한다면 Boolean 반전 대신 `active % N + 1`로 순환하는 방식과
실행 후 특정 그룹으로 고정하는 방식을 사용할 수 있다. 성공한 단일 실행 후에만
다음 선택을 적용하는 기존 원칙과 큐/배치 제한을 함께 유지해야 한다.
